Privacy Policy for Neon Jumper – Jumping Home

Last updated: November 15, 2026 · Current Android release candidate has real advertising disabled; separate debug builds use Google demo ads for adults.

Current build: The Android application includes the Google Mobile Ads SDK and Google User Messaging Platform (UMP). The current release build (v0.1.8) does not request or display ads. Production ads for adults have been prepared in code but remain disabled until consent messaging, age safeguards, and data-flow checks are completed. Only a separate debug testing build requests Google's official demo ads for users classified as adults. Real-money ad serving is not enabled. We will review this policy and the consent flow before enabling real advertising.

2. Audience and age screening

The game is designed for children, teenagers and adults. It asks for a date of birth to assign a local age group. The complete date of birth is not stored permanently; the age group is stored locally. The age check can be repeated in Settings.

No ads are requested in the current release build. In the separate debug build, demo ads and ad SDK initialization are enabled only for users classified as adults (18+). Children, teenagers and users with unconfirmed ages do not receive demo ad requests from the game logic.

3. Local game progress

Neon Jumper stores progress locally, including unlocked stages, coins, orbs, stars, selected skins and effects, audio preferences, and control settings. The browser version uses browser storage; the Android version uses local WebView storage. No account with the developer or developer-operated cloud database is required.

Players can voluntarily export or import save files. The user chooses the save file location and controls any copies. The developer does not automatically receive these backups.

4. Google Mobile Ads SDK

The current Android release candidate includes Google Mobile Ads and UMP but does not load real ads. A separate debug version uses official Google demo ad units for adult testing. Demo ads do not generate advertising revenue, but the SDK may still communicate with Google and process technical information when initialized.

Depending on SDK usage and consent status, Google may process IP addresses (which can be used to infer approximate location), device or app identifiers, ad interactions, app interactions, and diagnostic or performance information for ad delivery, analytics, and fraud prevention. The Android advertising ID permission (AD_ID) is expressly removed from the current manifest, but other technical identifiers may still be processed. Google and its advertising technology partners may be recipients of data where those services are used. See Google's Privacy Policy for additional information about processing, retention, and international transfers.

Planned production ads: Once separately activated, adults may receive full-screen and optional rewarded ads. Google Mobile Ads may process IP addresses (approximate location), app and ad interactions, diagnostics, and app or device identifiers for ad delivery, measurement, and fraud prevention. The Android advertising-ID permission remains excluded. No ad requests are intended for minors or users with unknown age. The live-ad feature remains switched off in the current release configuration.

5. Consent and advertising safeguards

For adult debug testing, the application uses UMP to request consent information and display a consent form if required and made available through AdMob. A privacy-options entry is offered where required. Demo ads in the debug version are also blocked unless Google UMP explicitly indicates that ad requests are permitted. The release version does not currently initialize the advertising SDK to serve ads. The prepared ad flow requires an adult age classification and an affirmative UMP canRequestAds() result. If a consent update fails, a previous status may be relied on only if UMP itself still confirms that ad requests are permitted. Otherwise no ads are requested. We will publish and test the AdMob consent message and review family policies before enabling real advertising.

6. Retention, export and deletion

Locally saved game data generally remains on the device until it is deleted through in-game or device/browser functions. Exported backups remain wherever the user chooses to store them until deleted by the user. Google may process and retain technical data when demo ad services are active; the developer does not directly control Google's retention periods. For details, please consult Google's privacy information.

7. Contact by email

If you contact the developer by email, information you provide will be used to answer the inquiry, based on handling your request or legitimate interests under Article 6(1)(b) or (f) GDPR as applicable. Messages are generally retained only as long as necessary for the inquiry and any legal retention requirements. Please do not send unnecessary data relating to children.

8. Website hosting (GitHub Pages)

This information website is intended to be hosted by GitHub Pages. When visiting it, technically necessary connection data such as IP address, browser information and request times may be transmitted to GitHub's infrastructure and logged to ensure reliable and secure service. This is based on a legitimate interest in providing the website under Article 6(1)(f) GDPR. This site does not include custom visitor analytics, ad trackers or external web fonts. See GitHub's privacy statement for information about transfers and retention.

9. Privacy rights

Subject to applicable legal requirements, individuals may have rights of access, rectification, erasure, restriction, portability and objection, and may withdraw consent for the future. You may also complain to a data protection supervisory authority. To exercise your rights, email neon-nomad@gmx.de.

10. Updates

This policy will be reviewed when app functionality or advertising configuration changes, especially before live Google AdMob ads are enabled. The version published here applies.
